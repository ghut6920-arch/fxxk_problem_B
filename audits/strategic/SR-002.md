## P1-A failure grades (preregistered)

Order: configuration (inputs/expectations/version/parameters) → implementation (deviation from the frozen contract) → `model-variant` only if a correct implementation of a fixed representation/scheduler still systematically fails on legal input → `model-family` only if a reviewed theoretical counterexample kills the **family** mechanism, not a numeric method, parameter, or scheduler.

Same-model author of candidate and evaluator: a failing self-test means a defect on one or both sides; a passing self-test does not exclude a shared bug; a failing self-test must not be written as “C0 geometry is bankrupt.” Upgrade to mathematics requires independent analytic derivation, an exact small example, or a reviewed theoretical counterexample.

| Item | Default grade | Local repair | `model-variant` | `model-family` |
|---|---|---|---|---|
| G07 | `implementation`; wrong fixture/threshold → `configuration` | Feasibility–recession–vertex order; exact/interval/certified predicates; fix wrong expectations | A fixed numeric representation/classifier cannot produce the required state on legal input, not a coding error | Reviewed theoretical counterexample against wedge modelling or Q1 core geometry |
| T05 | Usually C1 `implementation`; wrong cap/depth read → `configuration` | Keep coarse cells at cap; fix split/merge/outward rounding/true-cell containment | A fixed quadtree variant must delete truth or cannot keep an outer approx under the stated caps | Proof that **no** reasonable finite conservative representation can keep task completeness with the C0 fallback |
| T08 | Usually C1 scheduler `implementation`; wrong `L` → `configuration` | Consecutive adaptive count; unique task creation; success cancel; fallback advance | A frozen scheduler variant admits legal histories with permanent starvation or duplicate creation, with the code correctly implementing its own rules | Proof that **all** “finite adaptive + C0 fair fallback” mechanisms fail to make finite progress |
| Ledger | `implementation`; bad injected script or cost config → `configuration` | Recompute on uniquely accepted actions; reject duplicate success; distinguish measure switch vs clear; keep shortest failing prefix | A fixed cost/state variant cannot stay consistent with official action semantics on legal traces | Verified official rules themselves reject the route’s cost mechanism or causal state |

G07b already proved unbounded: `BOUNDED` is implementation failure; `NUMERICAL_UNCERTAIN` is honest abstention but the property does not pass; `UNBOUNDED` plus a verified recession ray passes. G07 is a Q1 submodule; its failure does **not** automatically refute C0 scan/clear constructions.

T05 tests C1 finite-outer capacity, not a C0 property. On T05 failure: pause affected C1; C0 does not fail; C2 pauses because it depends on C1 state; do not write “all finite-set methods failed.” Changing 4096/8 is a configuration change and must be re-reported.

T08 mainly tests C1 fairness and fallback queues; failure blocks C1/C2 variants. Only if the shared C0 fallback itself is wrongly cancelled does the C0 **implementation** pause; that remains a shared-code implementation defect, not an analytic C0 cover failure.

Ledger failure blocks C0/C1/C2 **cost** results, synthetic performance comparison, rehearsal time claims, and formal readiness. It does not refute spatial cover. Required wording: geometry was not refuted by this ledger error, but cost and run evidence from this implementation are unusable.

Repair: at most two substantive retests per round; do not move mathematical thresholds to fit scores; a config change retires old scores; changing state representation, scheduler, or scoring reopens as `model-variant`; only theoretical counterexamples or official-rule conflict trigger `model-family` review. Fixtures used for repair become regression sets, not unseen challenges.
