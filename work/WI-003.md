# WI-003 — Minimal Git Collaboration Protocol

- Status: `IN_PROGRESS`
- Owner Role: Technical Lead
- Related Goal: Repository collaboration reliability; operational support only, with no change to the current competition goal
- Base Commit: `15e5f863e3b6fecf1d59d254e0e50ebdfeb866eb`
- Work Type: Governance maintenance; not modeling and not an experiment

## Objective

Define the minimum pre-task, execution, completion, review, and integration Git protocol needed for Technical Lead, Executor, and Red Team worktrees to exchange reproducible, versioned outputs without automatic history mutation or unauthorized remote writes.

## Inputs

- `AGENTS.md`
- `work/README.md`
- `docs/roles/tech_lead.md`
- `docs/roles/executor.md`
- `docs/roles/red_team.md`
- `audits/technical/TR-TEMPLATE.md`
- Current three-worktree failure evidence from `WI-001`, `TR-001`, and the Red Team smoke output

## Allowed Scope

- Create and maintain this `work/WI-003.md`.
- Update `AGENTS.md` with one authoritative Task Git Protocol.
- Update `work/README.md` with the minimal WI status lifecycle and next identifier.
- Add role-specific protocol responsibilities to:
  - `docs/roles/tech_lead.md`;
  - `docs/roles/executor.md`;
  - `docs/roles/red_team.md`.
- Create `audits/technical/TR-003.md` and perform bounded documentation checks.
- Commit only the seven files named in this Allowed Scope.

## Forbidden Scope

- Do not change modeling strategy, assumptions, rules, data findings, experiments, results, formal artifacts, or the Primary Integration Goal.
- Do not modify, rewrite, close, or delete `WI-001`, `SMOKE-001`, `TR-001`, or any Red Team smoke evidence.
- Do not sync, rebase, merge, reset, delete, or repoint any existing role branch or worktree.
- Do not push any branch or tag, configure credentials, or broaden remote-write authority.
- Do not create automatic pull, merge, rebase, push, or history-rewrite behavior.

## Required Outputs

- An authoritative Task Git Protocol in `AGENTS.md`.
- Minimal WI statuses and transition ownership in `work/README.md`.
- Role-specific Git handoff duties in the three named role files.
- `audits/technical/TR-003.md` with an actual disposition.
- This WI updated to its reviewed final status.

## Acceptance Criteria

- Every task records a full Base Commit, assigned worktree/branch, authorized paths, tests, and explicit commit/push permissions.
- Agents must report path, branch, HEAD, and status before work and stop on mismatch; they must not repair the mismatch themselves unless a WI explicitly authorizes that repair.
- Technical Lead owns branch preparation, base synchronization, WI status changes, fixed-commit review coordination, and integration.
- Executor and Red Team completion reports include the full result commit, changed paths, tests, push status, failures, and remaining issues.
- Remote writes require explicit user authorization; a WI alone does not grant that authorization.
- Active reviewed history cannot be rewritten; commit references are validated before review.
- WI lifecycle uses only `READY`, `IN_PROGRESS`, `REVIEW`, `FIX_REQUIRED`, and `COMPLETE`, with Technical Lead as status owner.
- Documentation contains no conflicting instruction that tells ordinary task agents to auto-sync or auto-push.
- Only the seven authorized files change across the implementation commit.

## Stop Conditions

- Stop after the protocol, role refinements, WI status update, checks, Technical Review, and bounded commit are complete.
- Stop if an overlapping pre-existing change appears in an authorized file or if implementation would require modifying a forbidden artifact.

## Escalation Conditions

- Escalate to the user if remote-write behavior, credential configuration, automatic synchronization, or history rewriting is requested.
- Escalate according to `AGENTS.md` if any proposed protocol change would alter modeling authority, strategic decision ownership, formal gates, or review authority.

## Completion Boundary

Completion establishes an operational Git handoff protocol only. It does not demonstrate that `SMOKE-001` passed, synchronize existing branches, authorize remote uploads, or begin competition modeling.
